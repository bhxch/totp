# 设计：跨端同步——桌面端定时同步，扩展端跟随（验收条目 2）

## 背景与目标

桌面端与浏览器扩展是两套独立 vault（无直连通道），跨端汇合依赖云盘上的端到端加密
envelope。目标：桌面端新增条目后，扩展端在解锁状态下无感跟随，无需手动点同步。

## 现状

- 桌面端：变更后 10s 防抖自动推送云盘（`autoBackup.ts`，`DEFAULT_DEBOUNCE_MS=10_000`）+
  定时（≥15min）双向调度；推送前内容 hash 门（`cloudRunner.ts`，未变零网络请求）。
- 扩展端：自动拉取调度器**仅挂在 options 页存活期**（`entrypoints/options/App.vue`）；
  popup 平时点开即关，感知不到云端更新。
- 冲突语义（`syncOrchestrator.ts`）：远端未变本地变 → 推送；远端变本地也变 →
  **云端胜出 + 本地存加密冲突副本**，多目标收敛回推。
- 数据形态：云端恒为加密 envelope；**云盘凭据（CloudCred）存 DEK 保管区**
  （`saveSourceCredOp`，锁定态 credsCache 清空）——扩展 service worker 锁定态拿不到凭据，
  也拿不到 DEK。

## 方案修正（相对头脑风暴时的批准方案）

原方案为「扩展 chrome.alarms 后台定时轻检查」。探索确认一个硬约束：
**轻检查也要发云盘请求 → 需要云盘凭据 → 凭据在 DEK 保管区 → 锁定态 SW 无凭据**。
把凭据缓存进 `chrome.storage.session` 可绕过，但削弱"锁定态清凭据"的安全承诺，不采纳。

修正为：**解锁前台轻轮询 + 解锁钩子即时拉取**。这覆盖核心体验（打开扩展即最新），
保持安全模型不变；真后台静默检查列为二期可选（见非目标）。

## 设计

### §1 调度器抽取（扩展端）

`entrypoints/options/App.vue` 内联的调度逻辑抽为 `apps/extension/src/syncScheduler.ts`：
popup 与 options 共用；职责：解锁态下按间隔（默认 3min，可配）触发
`cloudRunner.run('pull')`，并暴露 `syncNow()`。

### §2 扩展端跟随语义

1. **解锁完成钩子**：vault 解锁成功 → 立即 `syncNow()`（清一次积压）。
2. **前台轻轮询**：popup 或 options 存活且解锁态 → interval 轮询（3min；
   envelope 下载后仅 hash 比对，无变化零处理）。
3. **锁定态**：不做任何网络请求；如上一轮检测到过更新且未应用，解锁后由钩子补上。
4. **推送**：沿用现有 commit 后自动 push（`store.ts onCommitted`）。

### §3 桌面端

维持现状（10s 防抖推送 + 定时双向），即"桌面端定时同步"本体；不改代码。

### §4 冲突与安全

- 冲突沿用 syncOrchestrator（云端胜出 + 本地加密冲突副本），无新增逻辑。
- 全链路保持端到端加密：网络上只有 envelope 密文；锁定态零网络行为。
- 设置项：`自动跟随云同步`（默认开）；关闭后退回纯手动同步按钮。

## 错误处理

- 网络失败：静默，下个周期重试（不打扰前台）。
- 凭据失效（401/403）：暂停自动调度 + SyncCard 状态区提示重新授权。
- envelope 下载失败/校验失败：同现有手动路径的错误呈现，不自动重试风暴。

## 验收

- 单测：syncScheduler 状态机（解锁/锁定/禁用三态、间隔触发、并发去重）；
  hash 无变化零处理路径。
- 手动两设备场景：桌面加条目 → 10s 内上云 → 扩展 popup 打开（已解锁）→ 3min 内
  或下次打开即见新条目；断网恢复后自愈。
- 回归：现有 backup/cloud 卡片与手动同步不受影响。

## 非目标（二期候选）

- `chrome.alarms` 真后台检查（前置：云盘凭据 session 缓存的专项安全评审）。
- native messaging 直连桌面端（体验上限更高，独立立项）。
- 多云盘目标的选择性同步策略变更。
