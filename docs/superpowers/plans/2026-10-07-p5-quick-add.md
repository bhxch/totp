# P5 扩展端快捷新增 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 扩展端右键快捷新增全链路补齐——选中文本走 `parsePastedText` 全格式（otpauth/SteamGuard JSON/base32 等，P2 产出）、data: URL 图片右键识别、Chrome `openPopup` 自动进新增确认态、Firefox 无 `openPopup` 时通知引导（点击打开 popup.html 完成 confirmed 添加）。

**Architecture:** background 两个既有菜单（`otpauth-add` selection / `qr-decode-image` image）升级：选中文本不再本地只认 otpauth URI，交 `parsePastedText` 嗅探（单条→pending、多条→引导主界面态导入页）；pending 存储从裸 URI 字符串升级为带 kind 的 JSON 信封（向后兼容旧裸字符串）；popup 消费端按 kind 分派（uri→`applyOtpauthPrefill`、pasted 单条→构造哑值 OtpEntry 预填 EntryForm 确认态）。

**Tech Stack:** WXT MV3 SW + vitest（`apps/extension/test/` 既有 background/popup 测试基建）。

**Spec:** `docs/superpowers/specs/2026-10-06-seven-features-design.md` §5；依赖 P2（steamGuard 格式进 `parsePastedText`）与 P4（popup 快捷新增确认态保留、EntryForm 无 Tab 渲染）。

## Global Constraints

- pending 信封格式（单一事实源，`apps/extension/src/pendingOtpauth.ts` 定义）：
  ```ts
  export interface PendingOtpauth { v: 1; kind: 'uri' | 'pasted'; text: string }
  export function encodePending(p: PendingOtpauth): string   // JSON.stringify
  export function decodePending(raw: string): PendingOtpauth | null // JSON 解析失败/形状不符 → null（调用方按旧裸 URI 兼容处理）
  ```
  兼容规则：storage 中的值 `decodePending` 返回 null 且非空 → 视为旧格式裸 URI（`{ kind:'uri', text: raw }`）。`PENDING_OTPAUTH_KEY` 常量不变。
- background 校验语义：选中文本 `parsePastedText` 结果 `entries.length === 0`（含 unsupported）→ `notify` 文案透传 unsupported 提示或"未识别出可导入的条目"，**不**写 pending、**不** openPopup；≥1 条 → 写 pending（kind='pasted'）+ openPopup 尝试。
- data: URL 图片：`fetch(dataUrl)` 在 MV3 SW 可用（fetch 支持 data: scheme），解码链路复用 `decodeImageBytesToUri` 不改；仅补测试证明 data: 分支（mock fetch）。
- Firefox 回退：`canOpenPopup()` 为 false 时发带自定义 id 的通知（`totp-pending-add`），`notifications.onClicked` 中该 id → `tabs.create(popup.html)`（popup.html 作标签页打开自动走 `consumePendingOtpauth`——`ext+otpauth` 协议先例同路径）。
- 测试命令：`pnpm -F @totp/extension test`；三端 typecheck。

### Task 1: pendingOtpauth 信封 + background 双菜单升级

**Files:**
- Modify: `apps/extension/src/pendingOtpauth.ts`（encodePending/decodePending + PendingOtpauth 类型）
- Modify: `apps/extension/entrypoints/background.ts`（selection 菜单处理分支重写；QR 分支写 pending 改信封；Firefox 通知回退；`notifications.onClicked` 监听）
- Test: `apps/extension/test/`（pendingOtpauth 与 background 既有测试文件追加）

**实现要点：**
1. selection 分支：`(info.selectionText ?? '').trim()` → `parsePastedText(text)`（import 自 @totp/core）——`entries.length === 0` → notify（unsupported 时透传其文案，否则"未识别出可导入的条目"）；否则 `encodePending({ v:1, kind:'pasted', text })` 写 pending 键 → openPopup 尝试（现有 canOpenPopup 块原样）；`entries.length > 1` → notify"识别到 N 条，请打开主界面导入页完成批量添加"（仍写 pending 单条场景只写单条？多条时不写 pending——批量在导入页做，notify 即可）。**单条**：`encodePending({ v:1, kind:'pasted', text })`。
2. QR 分支与 selection 的 uri 场景统一信封：QR 成功 `encodePending({ v:1, kind:'uri', text: uri })`。
3. Firefox 回退：openPopup 块 else 分支（`canOpenPopup()` false）→ `ext.notifications.create({ id: 'totp-pending-add', type:'basic', iconUrl:'/icon/128.png', title:'TOTP 验证码工具', message:'已识别待添加内容，点击完成添加' })`（fire-and-forget 同 notify 口径）；`notifications.onClicked.addListener((nid) => { if (nid === 'totp-pending-add') void ext.tabs.create({ url: ext.runtime.getURL('popup.html') }) })`——SW 顶层注册（幂等，重复 addListener 在 SW 生命周期内仅一次；defineBackground 每次冷启动跑一遍，listener 挂在事件_target 上天然单例）。
4. notify() 保持不变（无 id 的默认通知点击不动作——onClicked 分支只认 totp-pending-add）。
