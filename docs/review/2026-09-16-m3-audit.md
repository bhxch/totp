## 三、专题裁定

### 专题一：「复选框底色偏深」最终定位（用户原始反馈）

**结论：MdCheckbox 本身合规；偏深感来自 popup 的原生 checkbox（已修）与深色模式整体观感，tokens 无错。**

1. MdCheckbox 未选中=透明底 + 2px on-surface-variant 描边（MdCheckbox.vue:25-27），浅/深两模式特写均无填充色（checkbox-unchecked-dark.png）。选中=primary 实底（security-light.png 蓝底白勾 ✅）。
2. tokens.css 核对：`surface-container-highest` 浅色 **#e4e2e6（浅灰，正确）**、深色 #343438（正确，≈M3 neutral 90/20 两档）。假设「误用深色模式值」不成立——MdTextField 填充在浅色截图里就是浅灰（settings-light.png），深色下 #343438 也是深色模式的正确容器色。
3. 真凶：popup「按当前站点过滤」用 UA 原生 checkbox——color-scheme 随主题（tokens.css `color-scheme: dark`），原生控件在深色下**未选中即深灰填充**、选中态为系统 accent 色，与 M3 视觉割裂且跨平台不一致。修正为 MdCheckbox（F4）。次因：BackupCard 原生 radio 同类问题（F5 挂账）。

### 专题二：MiniApp 密文字档挂账裁定（Task 15 遗留）

**裁定：MiniApp reveal-secret 统一迁 `--md-sys-typescale-code-large`（18px），不新增 code-medium 档。**

- 依据 1（同屏一致）：MiniApp 复用 OtpListItem，列表验证码已是 code-large 18px；同窗内揭示密文却 16px，同屏双档更刺眼。
- 依据 2（跨端一致）：options/popup/desktop 主界面的揭示密文（RevealDialog.vue:33、OtpListItem.vue:87）均 code-large。
- 依据 3（档位经济）：code-medium 仅此一处消费，新增档位是规范外发明。MiniApp.vue:94 `body-large` → `code-large`。

### 专题三：色彩角色与字阶总体

- 全仓扫描（ui 包 + 宿主）：硬编码色仅 SettingsPage.vue:124 `.theme-dot__check { color: #fff }`——位于任意色相的调色板圆点上，无对应 sys-color 角色，**判定为例外合理**，保留。
- 字阶：Task 15 后全部 `var(--md-sys-typescale-*)`，无遗漏 px 字号；唯一例外 MdDialog headline 20px 为记录在案例外。

### MdSelect 弹层夹取专题（批 3 必查项①裁定）

- **缺陷实锤（小修前）**：触发框 bottom=692、视口 900 时，`EST_HEIGHT(280)` 估算夹取把弹层推到 top=612 < 692，**遮挡触发框 80px**（弹层实际仅 172px 高，估算远大于实际导致过推）。
- **小修**：渲染后（nextTick）按弹层实际高度校准，三分支取「不遮挡且不溢出」者——下方放得下→正下方（bottom+8）；下方放不下且上方更宽裕→向上翻转（top−8−h）；上下都放不下→贴视口底内边距夹取。补 jsdom 行为测试 3 条（mdSelect.test ⑭⑮⑯，stub 布局驱动）。
- **修复后实拍**：未滚动 top=700=692+8；滚到视口底部再开 top=653=645+8，均 `overlaps=false`/`overflowsViewport=false` ✅。翻转/贴底分支受页面布局所限（滚到底时触发框下方恒有 254px>弹层 172px）无法天然触发，以 ⑮⑯ 源码级行为测试覆盖。
- 其余两项判定：弹层正对触发框、宽 120px（min-width）与触发框 ~103px 观感协调；hover/选中高亮与键盘 ArrowDown+Enter（高亮移动→选中回写→焦点回触发框）均 ✅。
- **hover 状态层缺陷（同轮小修）**：弹层选项原仅键盘 active 有高亮，纯鼠标悬停无任何反馈——补 `:hover` 8% on-surface state layer（`:hover` 声明先于 `--selected`，选中项容器色不被覆盖），实测 hover 色 `color(srgb 0.106 0.106 0.122 / 0.08)` ✅，源码断言见 mdSelect.test ⑰。

### MdMenu 外点关闭缺陷（同轮小修）

菜单开启后点击页面其他区域原不收起（组件仅 Esc、宿主仅点选收起）——照 MdSelect 自包含模式补 document mousedown 外点关闭（容器内不误关；open 翻转随卸载监听），jsdom 行为测试 1 条（mdOverlays.test），实拍外点关闭 ✅。已知边界（记录不修）：菜单开启时再点触发按钮，mousedown 先关、click 再开，净效果为重开（与 MdSelect 既有行为一致）。

### 同批功能落地（recordStatus 三态，详见 commit e675b66）

自动备份/云同步 runner 的 `recordStatus` 改三态 `(ok: boolean | null, summary)`：锁定/无口令/未启用目标记「跳过：…」（null），unchanged 维持静默；两端宿主格式化为「YYYY-MM-DD HH:mm 跳过：summary」，旧 JSON（ok 恒 true/false）渲染不变。手动同步走 CloudCard 自身链路不经 runner，记录无污染；跳过态写入频率受防抖 10s / interval ≥15min 约束，每次触发事件至多 1 条。
